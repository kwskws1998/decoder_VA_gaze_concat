# Corrected redistribution input alignment: corpus validation

## Result

The corrected production alignment and ET2 feature mapping passed an independent
character-offset check on **all 14,352 archived experiment texts and all 270,714
ET segments**. No segment was assigned to another occurrence, left unmapped, or
anchored to a whitespace-only or special token.

That historical audit and its recorded results were not regenerated by this
validation.

## Implemented correction

- [`alignment.py`](../../va_model_code/decoder_va/alignment.py) replaces token-text
  search with exact source-character spans and verified tokenizer offsets. It
  checks complete visible-character coverage and never normalizes distinct
  Unicode occurrences into the same string.
- [`gaze.py`](../../va_model_code/decoder_va/gaze.py) aggregates valid source
  predictions at shared destinations and includes the alignment version in its
  raw-feature cache key. The ET tokenizer must provide its original word IDs.
- Saved model and run metadata record the complete version-2 `gaze_alignment`
  policy. Loading or resuming historical gaze weights with the corrected mapping
  is rejected; historical text-only compatibility is preserved.
- The Gaussian kernel and its optimizer settings are unchanged. All raw, fixed,
  and learned gaze conditions receive the corrected input alignment.

For `I love this!!! I hate that!`, uniquely numbered source TRT values 1 through
10 now become `[1, 2, 3, 15, 7, 8, 9, 10]` at the eight Qwen tokens. The three
adjacent exclamation marks contribute `4 + 5 + 6 = 15` to `!!!`; the final `!`
retains its own value, `10`. The old mapper assigned the first exclamation mark
to that final token and lost the intervening words.

Unverifiable tokenization fails explicitly. In particular, truncation inside a
multibyte character can prevent a decode/re-encode round trip. None of the actual
archived texts triggered that failure. Supporting such cases later requires
preserving original tokenizer offsets through the data pipeline.

This uses the same archive and pinned Qwen tokenizer files as the original audit.
Each sentence is tokenized with the experiment's 200-token truncation, decoded
with special tokens removed, and segmented by the production ET2 segmenter. The
independent oracle checks occurrence identity using source character intervals
and the fast tokenizer's offset metadata. It verifies that decoded text
retokenizes to the exact same IDs before comparing mappings.

Every source segment must map to **all visible Qwen tokens that overlap its own
character interval**; its feature is anchored to the first such token. This
comparison does not call production alignment helpers to generate expectations.

## Shared tokens and feature preservation

Some Qwen tokens cover multiple ET segments. This is common for merged
punctuation, contractions, and multilingual text, and must not cause feature
overwrite or occurrence search jumps.

- **6,678 sentences** contain at least one shared first-token destination.
- **11,736 target positions** receive multiple source segments.
- **15,183 additional source segments** share those destinations.
- The corpus has **255,531 unique valid gaze positions** after aggregation.

The actual `ET2GazeProvider._map_predictions_to_target` method was invoked twice
for every sentence, with uniquely numbered synthetic TRT values:

1. Every source segment valid and finite.
2. Every seventh source masked out and every eleventh source nonfinite.

All **28,704 provider checks** matched independently computed destination values
and masks exactly. All **28,704 total-TRT checks** conserved the included source
values exactly. Invalid sources were excluded before aggregation; invalid target
positions remained exactly zero.

Additional sampled and constructed checks exercised all five ET channels:
`nFix` and `TRT` sum when destinations collide; `FFD`, `GPT`, and `fixProp` use the
mean of valid source predictions. The expected values were computed independently
per destination. Every check passed.

This aggregation is an explicit representation choice necessitated by ET/Qwen
segmentation differences. Validation establishes correct execution of that
choice, not that it is the unique best representation for VA prediction.

## Redistribution after corrected mapping

Constructed cases include repeated punctuation, abbreviations, contractions,
whitespace, CJK text, composed/decomposed accents, fullwidth characters, and emoji.
Every 500th corpus row was additionally sampled for downstream checks.

Across **160 kernel cases**, the corrected mapped TRT was redistributed with
widths `(0.5, 2.0)` and `(2.0, 0.5)`, each with CPU BF16 autocast disabled and
enabled. All outputs were finite, all invalid positions stayed zero, and all TRT
totals matched within the stated FP32 tolerance (`rtol=3e-6`, `atol=2e-4`). The
largest observed absolute total difference was **3.0517578125e-5**. Kernel output
remained FP32, as required by its compute contract.

## Regression and training integration tests

The final offline suite passed **578 tests**, with **one CUDA-only test skipped**
because CUDA is unavailable on this host:

```bash
python -m pytest -q -ra va_model_code/tests diagnostics/redistribution_audit_20260922/test_alignment_regression.py
```

The 29 dedicated character-alignment regressions cover punctuation, contractions,
Unicode, collisions, finite/valid source masks, signed features, partial offsets,
and unsafe tokenization round trips. Two additional integration cases run the
actual provider's `compute` and cache path with deterministic offline ET assets,
then pass the corrected gaze through a randomly initialized native hybrid
Qwen3.5 decoder with gradient checkpointing, in FP32 and CPU BF16. Both sigma
gradients are finite and nonzero, both parameters update with zero weight decay,
and cached raw TRT stays identical after two optimization steps. ET inference
runs once for duplicate inputs and receives no gradient.

Checkpoint tests cover the saved alignment policy, strict corrected-model
reload, rejection of incompatible historical gaze weights before backbone
loading, and continued historical text-only compatibility. Python compilation
and `git diff --check` also pass.

## Limits

No ET2 or VA model weights were downloaded or loaded. Synthetic features verify
alignment, aggregation, and redistribution mechanically. They do not measure
ET2 prediction quality, ET2-side truncation coverage, learned sigma behavior, or
downstream performance after retraining. Existing experiment scores cannot be
treated as results from the corrected pipeline. Matched experiments must be
rerun to quantify the effect of the fix.
