Finding 1 — P1: BF16 storage loses full-finetuning updates at LR 6e-6
train_model.py:435-438 selects torch.bfloat16 as model storage dtype.
decoder_va/model.py:530-551 passes it to from_pretrained, then makes the backbone
trainable. The full path returns it without FP32 master parameters.
With torch2.12.1, transformers5.16.1 and accelerate1.14.0, the actual
VARegressionTrainer default AdamW fused optimizer preserves BF16 parameter and
moment storage. Native autocast/output conversion does not create FP32 masters.
Constant-gradient scalar0.02001953125 remains unchanged for100steps at6e-6;
FP32 scalar0.02 changes to0.019399855. This occurs with fused and ordinary AdamW.
Small native Qwen,10steps:8.786% of backbone elements with a nonzero initial
gradient changed with BF16 storage, versus99.995% with FP32 storage/BF16 compute.
The latter changes normalization precision too; this is a path reproduction,
not a controlled test of eventual model quality. The scalar test isolates loss
of parameter updates. Separate actual-Trainer/small-Llama reproduction confirms
the same optimizer storage behavior. Neither experiment measures the actual
trained0.8B change fraction or establishes the cause of left/right ranking.
Recommended correction: separate parameter storage from compute precision;
retain FP32 trainable parameters/master weights while using BF16 autocast.
Do not change sigma LR to compensate: current log-sigma parameters are FP32.
Evidence: precision_probe.py/json; sigma_training_precision_audit_oct13.py/json.

Finding 2 — P1 compatibility: ET2 preprocessing differs from pinned inference
decoder_va/gaze.py:166-187 isolates punctuation/symbol/CJK characters.
Lines442,465-471 pass these as separate pretokenized words with prefix spaces.
Pinned skboy/et_prediction_2 model.py:129-149 uses text.strip().split() and the
first token of each inferred whitespace word. It also clips negative predictions;
current code deliberately retains signed raw values. Negative clipping effects
were not measured here and should not be silently changed as part of sigma tests.
For "I'm sad!!!":
  Official words: ["I'm", "sad!!!"]
  Current segments: ["I", "'", "m", "sad", "!", "!", "!"]
  Official IDs: [0,38,437,5074,16506,2]
  Current IDs:  [0,38,128,475,5074,27785,27785,27785,2]
Pinned slow/fast tokenizer IDs agree for the inspected examples. Corpus-wide,
13,166/14,352 rows (91.736%) differ in ET2 input IDs under the two preprocessing
rules. Current segments270,714 versus whitespace words214,877. This changes both
contextual input and feature extraction anchors, not merely an index mapping.
This establishes divergence from published inference, NOT verified divergence
from training preprocessing (training code/weights were not evaluated).
Recommended correction/validation: specify and test the predictor preprocessing
contract, use its intended input convention or validate the alternative explicitly,
version this change, and rerun raw/fixed conditions together.
Evidence: review_et2_preprocessing_oct13.py/json; et2_pinned_inference_source.py.

Finding 3 — P2: final regression head/activation discard precision
decoder_va/model.py:410-411 runs the head under autocast then hardsigmoid in BF16.
losses.py casts predictions to FP32 only afterwards. This cannot recover lost bits.
BF16 logits[-.001,0,.001] all become0.5; FP32 activation preserves
[.4998334,.5,.5001666]. Actual latest OOF predictions are all on the BF16 grid;
on[.5,1) spacing is1/256. This can hide small sigma sensitivities and makes losses
depend on rounded predictions, but it does not imply zero analytical gradients
everywhere. Only58arousal outputs per latest run were at0/1, and no valence
outputs, so broad activation saturation is not established.
Recommended correction: run the regression head and final activation outside
autocast in FP32, with FP32 head parameters; casting final predictions alone is
insufficient.

Finding 5 — P3 latent robustness: first-subword fallback after nonfinite output
decoder_va/gaze.py:517-534 conflates whether a word was seen with whether a finite
feature was accepted. A NaN first-subword output is skipped without marking the
word seen, so a finite later subword is silently substituted. A fake predictor
reproduces this. There is no evidence it occurred in these experiments.
Recommended correction: track first-subword occurrence independently of validity,
or fail fast with an explicit predictor error.

Reference-only bug and compatibility differences
reward_model_base.py:214-225 checks the redistribution enable flag only in v1.
In v2 with TRT selected it always applies the kernel, even if the flag is false.
The constructor merely freezes its sigmas when disabled. Input[0,1,0] then becomes
[.27406874,.45186251,.27406874] under a supposed disabled1/1setting.
This affects a raw-baseline interpretation ONLY IF that reference code path was
used; the original run's flags are unknown, and CLI default is predictor1.
Pinned eyetrackpyv1.0.0 predictor1 is BiLSTM with T5-token coordinates, predictor2
is RoBERTa with RoBERTa-token coordinates. Current VA uses Qwen first-subword
coordinates. Referencev2 masks non-first predictions to zero but can retain
ordinary-token destinations; current VA excludes nonanchors as destinations.
Therefore identical numerical sigma values need not implement the same operator.
