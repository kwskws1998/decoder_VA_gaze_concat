Redistribution review fixes — 2026-10-13

Scope
The existing held-out evaluation fold continues to select the best epoch and
supply final reported predictions. No independent validation split was added.
The redistribution kernel direction, mask, normalization and sigma coordinates
were verified and retained. The reference reward implementation is a historical
snapshot, not imported by this pipeline; it was not silently rewritten.

Implemented
1. Every trainable parameter is stored in FP32, including a directly supplied
   backbone. Full fine-tuning requests FP32 base weights. LoRA may retain lower
   precision for its frozen base. BF16/FP16 remains the autocast compute mode.
   The complete regression head and hard sigmoid run in FP32 outside autocast.
2. ET2 uses whitespace pretokenization, the first active subword, nonnegative
   clipping and fail-fast handling for nonfinite selected predictions, matching
   the pinned companion inference convention. The generic alignment remapper
   retains its signed-feature aggregation behavior. Failed inference cannot add
   partial results to the cache or substitute a later subword.
3. Training excludes NFKC/casefold/whitespace-normalized texts found in the
   evaluation fold. Evaluation rows/order/labels and original fold files are
   preserved. Dry-run validates the effective training set before downloads.
   Root and per-fold manifests record the policy and exclusions; resume,
   packaging and external overlap analysis validate these records.
4. Architecture schema8 and alignmentv3 prevent reinterpretation of historical
   checkpoints. Actual trainable safetensors dtypes are checked before reload or
   resume. External inference uses compute_dtype separately from parameter
   storage dtype. Historical schema6/7 result packaging remains supported.

Interpretation and limits
These tests establish software behavior, not improved task performance or a
rightward advantage. Actual 0.8B/ET2 GPU training and VRAM use were not measured.
FP32 trainable storage requires more memory than the historical BF16 storage.
Start fresh, matched raw/right/left runs under the new contracts; old weights
cannot recover optimizer updates lost during their original training. Keep old
results labelled as historical; no old metrics or checkpoints were rewritten.
